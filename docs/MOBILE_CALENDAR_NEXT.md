# 모바일 캘린더·공유·홈 화면 위젯

2026-11-05 요청 기준. 아래 공유·위젯 항목은 구현 완료 목록이 아니라 후속 개발 명세다.

## 모바일 화면

- 767px 이하에서 작은 월간 달력을 항상 위에 표시한다. 아래 `일정 / 할 일`은 탭 또는 좌우 스와이프로 전환한다.
- 모바일 달력도 설정한 간단/상세 보기를 따른다. 달력은 전체 높이로 표시하고 아래 일정/할 일까지 페이지 하나로 연속 스크롤한다. 상세 달력은 작은 날짜·칩 글씨를 사용하고 칩은 한 줄로 표시하며, 너비를 넘는 제목은 말줄임표 없이 잘라 표시한다. 날짜 사이 세로선은 표시하지 않는다.
- 날짜 선택은 달력, 일정, 할 일 강조에 동일하게 반영한다.
- 할 일의 `시간 배정`은 기존 편집창을 열고, 단일 할 일의 날짜를 선택 날짜로 채운다. 확인하기 전 저장하지 않는다. 시각은 사용자가 직접 지정한다.
- 반복 할 일의 날짜는 반복 시작일이므로 자동 변경하지 않는다. 개별 회차 이동은 예외 회차 모델을 도입한 뒤 지원한다.

## 공유 캘린더 — 아직 구현되지 않음

현재 공유 타입은 예약되어 있지만 DB 권한과 일정 저장은 개인 소유자 중심이다. 화면에 공유 버튼만 추가해서는 동작하지 않는다.

### 기능 범위

- 생성·이름·설명·기본 색상 변경, 개인별 표시/숨김 및 표시 색상.
- 가입된 이메일로 초대, 초대함, 수락·거절·취소·만료·재초대. 초대 메일 발송은 메일 제공자 연결이 별도로 필요하다.
- 소유자 / 편집자 / 열람자. 소유자만 멤버 초대·권한 변경·추방·소유권 이전·캘린더 삭제가 가능하다.
- 편집자는 공유 일정·할 일 생성·수정·삭제·완료, 열람자는 조회만 가능하다. 날짜만 있는 할 일·종일·반복 일정도 지원한다.
- 탈퇴, 마지막 소유자 보호, 계정 삭제 전 소유권 처리. 삭제·이동은 확인을 거친다.
- 일정에 캘린더 선택, 작성자 표시, 변경 내역, 실시간 갱신 및 재연결 후 재조회, 충돌 시 재확인.
- 알림은 참여자별 설정으로 구분하고, 개인 메모와 개인 카테고리는 공유 데이터에 노출하지 않는다.

### 구현 순서와 통과 조건

1. 멤버십·초대 테이블과 인증된 RPC를 추가한다. 이메일 검색 결과가 사용자 목록 조회 수단이 되지 않도록 서버에서 처리한다. 수락은 초대 수신자만 가능하고 중복 수락은 멱등 처리한다.
2. 개인 캘린더의 기존 데이터는 보존하고 공유 캘린더 전용 권한을 추가한다. 일정·이력·카테고리·알림까지 모두 DB 권한을 검증한다. 기존 작성자·소유자 제약과 계정 삭제 동작도 함께 수정한다.
3. Repository의 사용자 필터와 저장 경로를 검토해 공유 일정 조회·편집을 지원하고, 캘린더 선택과 초대함 UI를 연결한다.
4. 실제 DB에서 소유자·편집자·열람자·비회원 각각의 읽기/쓰기, 초대 만료·취소·동시 수락, 권한 회수 직후 접근, 소유권 이전·탈퇴·계정 삭제를 검증한다.

## 안드로이드·아이폰 홈 화면 위젯 — 아직 구현되지 않음

현재 저장소에는 웹앱만 있고 휴대폰 앱 프로젝트·위젯 타깃은 없다. 홈 화면에 웹앱 바로가기를 추가하는 기능과 OS 위젯은 별개다.

### 네 종류

| 위젯 | 표시와 동작 |
| --- | --- |
| 월간 캘린더 | 날짜, 일정/할 일 표식, 선택한 날짜의 앱 화면 열기 |
| 할 일 | 선택 캘린더의 오늘/미완료, 체크 완료, 상세 화면 열기 |
| 오늘 타임라인 | 날짜만 있는 할 일과 종일 일정 상단, 시간순 일정, 현재 시각 |
| 빠른 추가 | 버튼을 누르면 앱의 입력창에 바로 진입. 위젯 내부 키보드 입력은 공통 기능으로 제공하지 않음 |

- 플랫폼별 OS 위젯을 만든다: 안드로이드 AppWidget/Glance, 아이폰 WidgetKit/App Intents.
- 공통 데이터 계약은 로컬 날짜·시간대·종일·시간 미지정·반복 회차·완료 상태를 구분한다. 웹의 반복 계산과 동일한 결과를 검증한다.
- 앱 인증 상태와 보호된 저장소를 연결한다. 공유 캘린더 멤버십을 서버에서 검사하고 서비스 역할 키를 기기에 넣지 않는다.
- 로그아웃·계정 전환·권한 회수 시 위젯 캐시를 지우며, 민감한 제목 숨김 옵션을 제공한다.
- OS가 갱신 주기를 제어하므로 초 단위 실시간을 보장하지 않는다. 마지막 갱신 시각·오프라인 상태와 실패한 완료 요청 재시도를 처리한다.
- iOS 빌드/서명/기기 검증에는 macOS·Xcode 및 앱 서명 설정이 필요하다. Android SDK·서명·실기기 검증도 별도 필요하다.
- 두 플랫폼에서 위젯 추가·크기 변경·오프라인·완료 처리·계정 전환·일광절약시간·공유 권한 회수·딥링크를 검증한 뒤 배포한다.

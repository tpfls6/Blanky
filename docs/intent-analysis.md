# 자연어 의도 분석 (복수 의도 · 기존 일정 변경)

"이번주 금요일은 1시 퇴근하고 도현오빠랑 데이트 있어"처럼 한 문장에 기존 일정 변경과
새 일정이 함께 있는 입력을 처리한다. 이전에는 AI 분석 오류 시 메모로 저장되었다.

## 흐름

홈 입력 → `captureIntent`(기록/대화 구분) → `analyzeIntents` → `planIntents` → 미리보기 또는 자동 실행.

1. 규칙 추출 `packages/parse/src/intents.ts`
   - 구어체·오타 정규화(낼, 담주, 금욜, 하구, 잇어, 3씨, 미뤄죠 …).
   - 절 분리(쉼표, 그리고, ~하고/~끝나고/~한 후 …)와 날짜 문맥 상속, 시간 관계(`afterId`).
   - 의도: create_event / create_task / modify / cancel / memo / diary / anchor.
   - 루틴 의미군(work: 근로·근무·알바…, school: 수업·강의…)과 경계 동사(퇴근/하교/끝나 → 종료, 출근/등교 → 시작).
   - 시각은 `ClockHint`로 보존하고, 오전/오후는 대상 일정을 기준으로 `resolveClock`이 결정한다.
2. AI 보조 `packages/parse/src/intentAnalysis.ts`
   - 규칙이 일정 신호가 있는 절을 해석하지 못한 경우에만 Edge `parse-schedule`의 `format: 'intents-v1'`을 호출한다.
   - 근거(evidence)는 원문 부분 문자열이어야 하며, 서버와 클라이언트가 모두 검증한다. 저장된 일정은 서버로 보내지 않는다.
   - AI 실패·미배포 시 규칙 결과를 그대로 사용한다.
3. 계획 `src/features/ai/intentPlan.ts`
   - 저장된 일정(서버에서 불러온 library.items)에서 제목·의미군·날짜로 대상을 찾는다.
   - 반복 일정의 하루 변경/취소/이동은 `seriesEdit`의 분할 방식(repeatUntil + seriesId)으로 처리해 반복 규칙을 유지한다.
   - 대상 없음·여러 개·날짜/변경 내용 없음·종료<시작은 질문만 하고 저장하지 않는다.
   - 시간이 없는 새 일정은 시간을 만들지 않고 질문한다(시간 없음으로 저장, 관계 메모 첨부).

## 자동 저장과 확인

- 자동 실행: 비반복 단일 일정의 명확한 변경 등 위험 요소가 없는 경우.
- 미리보기 + 실행: 반복 일정 변경, 삭제, 시간 충돌, 오전/오후 추정, 시간·대상 미정, AI 분석 결과.
- 실행 시 미리보기 이후 바뀐 대상은 건너뛰고, 각 작업의 성공/실패를 따로 표시한다.
- 일정 신호(날짜·시각·일정 어휘)가 있는 문장은 분석 실패 시 메모로 저장하지 않고 오류를 보여 주며 입력을 복원한다.

## 테스트

- `npm run test:intent` (npm test에 포함): 예문, 구어체/오타, 복합 문장, 충돌, 불명확 정보, AI 검증, Edge 처리, 실행 격리.
- `npm run test:intent-browser`: 로컬(Supabase 미설정) 홈 화면에서 미리보기 → 실행, 다른 주 유지, 메모 미저장, 모바일.

## 배포

`intents-v1`은 Edge Function `parse-schedule` 재배포 후 동작한다. 배포 전에는 규칙 결과만 사용한다.

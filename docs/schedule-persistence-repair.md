# 일정 저장 및 시간 추천 운영 오류 수정 — 2026-10-29

운영 프로젝트 `drqauskbpizxjnfquktz`에서 직접 확인한 원인:

- `schedules.due_time` 누락: 전체 일정 PATCH에 이 필드가 포함되어 PostgreSQL `42703` / HTTP 400 발생.
- `user_pages` 누락: PostgREST `PGRST205` / HTTP 404 발생.
- 로컬 샘플 `task-exam`을 UUID 컬럼의 `id in (...)` 필터에 전달하여 HTTP 400 발생.

## 변경

- 완료 변경은 `updateStatus`로 `status`, `change_source`만 PATCH한다. 날짜, 반복, 카테고리, 마감 시각을 다시 쓰지 않는다.
- 시간 추천은 라이브러리가 서버에서 실제로 읽은 ID만 재조회한다. 로컬 항목은 로컬 원본으로 추천하고, 승인 시 기존 `commitWork` 경로가 서버 항목으로 저장한다.
- 서버 일정과 아직 서버에 저장되지 않은 로컬 일정을 모두 충돌 검사에 포함한다. 서버에서 삭제/완료된 할 일은 오래된 캐시로 대체하지 않는다.
- 명시적인 날짜로 나뉜 쉼표 목록은 AI 설정 유무와 관계없이 규칙 파서로 분리한다. 운영 AI 검증에서 발견된 3항목 목록 실패를 제거한다.

## 실제 반영

`supabase/repairs/20261029_schedule_pages_schema.sql`을 운영 DB에 적용했다. 기존 페이지 관련 마이그레이션 4개와 마감 시각 마이그레이션의 필요한 DDL 및 승인 함수 정의를 단일 트랜잭션으로 적용한다. 기존 일정 행은 수정하지 않는다. `user_pages`에 소유자 RLS와 인증 사용자 권한을 설정하고 PostgREST 스키마 캐시를 갱신한다.

`parse-schedule` Edge Function도 운영 프로젝트에 배포했다. 원격 DB에는 기존부터 마이그레이션 이력 테이블이 없어 전체 `db push` 대신 확인된 누락 항목만 명시적으로 적용했다. 이 SQL은 확인된 누락 상태에 한 번 적용하는 복구 파일이며 다시 실행할 파일이 아니다.

프런트엔드 수정은 저장소와 Vite 빌드에 반영했다. 별도 프런트엔드 호스팅 배포는 수행하지 않았다.
